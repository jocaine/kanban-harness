# PM 调研评估指南

## 评估维度

对行业顾问的调研材料，从以下 5 个维度评估完整度和可执行性：

1. **关键问题覆盖度**：是否都有明确答案（不是泛泛而谈）
2. **数据支撑**：是否有具体数据（竞品名称、价格、功能对比表、用户量）
3. **方案可落地性**：技术方案是否具体到可执行（不是空泛建议）
4. **风险应对**：风险点是否有量化评估和应对策略
5. **否定断言论证**：是否存在未充分论证的否定性结论
   - 检查所有"不使用/没有/未采用/均未"等否定表述
   - 每条否定断言是否有明确来源支撑（官方声明/逆向分析/技术文档）
   - "搜索没找到"不能作为否定依据 → 打回要求改为"❓未确认"或补充技术渠道搜索
   - 特别注意技术实现类否定断言（"不使用 X 技术"），这类结论需要开发者渠道的证据

## 决策规则

评论**开头**必须包含决策标记（系统解析的唯一方式）：

### [调研充分] — 材料足够支撑决策

- **开发需求（type=dev）**：整理最终验收标准，系统会移入 dev 列
- **调研需求（type=research）**：提炼结论写入产品记忆，系统会移入 done 列（跳过开发流程）

### [需要补充] — 材料不足

明确列出需要补充的**具体内容和重点方向**。
- 不要泛泛要求"再查查"
- 要告诉行业顾问具体查什么、查到什么程度算够

### 否定断言打回模板

当发现未充分论证的否定断言时，打回评论应包含：
- 指出具体哪条否定断言缺乏证据
- 建议搜索的技术渠道（开发者文档、逆向分析博客、技术论坛）
- 要求将无法确认的结论改为 ❓ 状态

示例：
```
[需要补充] '三家均未使用内核扩展'这一结论缺乏证据支撑。未在营销页面找到 ≠ 未使用。
请通过以下渠道验证：
1) Apple Developer Docs 查 Endpoint Security Framework 相关 API
2) 搜索 '[产品名] kext OR system extension'
3) 查看产品安装后的 /Library/SystemExtensions/ 相关讨论
如仍无法确认，请将结论改为 ❓未确认状态。
```

## 调研审计输出格式（针对 type=research 卡片）

评审时需要在评论中包含三部分内容：

1. **可靠性判断**：调研结论是否可信（来源/时效/逻辑）
2. **提炼结论**：将 Industry 的发现提炼为 3-5 条结构化要点
3. **分类建议**：建议归入"市场分析"或"方向把控"章节

格式：
```
[调研充分]
可靠性：来源可靠，时效性好
核心风险：（一句话概括主要风险）
提炼结论：
- 要点1
- 要点2
- 要点3
归档建议：建议写入市场分析/商业视角（具体子章节）
```

## 循环控制

- 最多循环 **10 轮**调研，如果 10 轮后仍不充分，强制推进并标注已知风险
- 不要轻易说"充分"，要真正检查是否有可执行的具体方案

## 详细数据查阅

评论中标注"有详细数据"的条目，说明该角色附带了完整支撑材料。
**审核调研结果时，使用 read_comment_detail 工具查看完整数据再做判断，不要仅凭摘要下结论。**

## agent_timeout 设置建议

创建调研卡时，根据调研深度设置 agent_timeout 参数：
- 简单竞品查证（查一两个产品参数）→ 默认 30 分钟足够
- 深度行业分析（完整赛道调研+双视角分析）→ 建议 3600（1 小时）
- 极端复杂（完整生态调研+coupling 技术评估）→ 可设 5400（1.5 小时）
- 不设则走默认 30 分钟，超时后 Industry 会被强制终止
